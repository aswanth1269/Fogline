# Fogline: An Adaptive Multi-Vector Cyber Threat Prediction Framework Using Temporal Graph Intelligence

Data science course project by Aswanth V (23BCE2030) and Sharan Mahendran (23BCE2310), VIT Vellore.

Fogline combines three layers.

1. **Edge layer.** Logistic Regression, Decision Tree and Random Forest score each connection, and a risk score is computed.
2. **Fog layer.** Only uncertain or high-risk cases are escalated. The fog model is chosen from confidence, validation F1 and forecast CPU/RAM load.
3. **Temporal graph intelligence layer.** Users, hosts, servers and external IPs are nodes, and network, identity, endpoint and alert events are timestamped edges. The TG-AMV model (time-encoded neighbourhood attention, adaptive vector weights and a GRU) predicts the next attack stage and the next likely victim.

The final report is in `report/Fogline_Final_Report.pdf` (editable `.docx` alongside).

## Demonstration

1. Open Traffic lab and run Normal, Uncertain, then Attack. Each run creates a synthetic feature vector, performs real ML inference, and saves an event.
2. Inspect model votes, risk, edge/fog routing, and recommended action.
3. Enter custom features to analyze a manual sample.

5. Open Model registry; download the CSV example, choose a compatible dataset, and train the models.

## Structure

- `frontend/`: responsive HTML, CSS and JavaScript application; overview, analysis, paginated event history and model registry.
- `backend/app.py`: Flask JSON API, validation, same-origin checks, request limits and operation lock.
- `backend/services/`: logistic regression, random forest, decision tree, resource trend predictor, risk engine and fog selection.
- `backend/storage.py`: SQLite event repository. `data/events.sqlite3` retains all events locally.
- `models/bundle.joblib`: atomically replaced model bundle, metrics, version and training source. Restored on restart. Only load bundles created by this app; joblib files are executable Python serialization.
- `tests/`: API, validation, persistence and model restoration tests.

Features: packet_rate, failed_logins, unique_ports, avg_packet_size, connection_duration, syn_ratio. Values must be finite and nonnegative; SYN ratio is between 0 and 1. CSV also needs label, exactly 0 or 1; 40–50,000 rows and at least four per class. Invalid datasets leave previous models active. Training serializes against inference; the local console waits until the operation completes.

## Research boundaries

This is a functional research prototype, not a production network defense service. It processes feature vectors, does not capture packets, and does not modify firewall rules. Default models train on synthetic data. Holdout metrics use a random stratified split and are not evidence of generalization to real chronological network captures. Report dataset provenance and perform independent chronological evaluation before making research performance claims.

Host CPU/RAM are real; forecasting is a recent-trend proxy. Risk and feature indicators are heuristics, not LSTM/Transformer or SHAP. There is no distributed federated learning; the misleading version-only sync control has been removed. Inference probabilities are uncalibrated. Actions such as Block + alert are recommendations only.

The server binds to localhost without debug mode. No user accounts, TLS termination, remote deployment, live capture or production retention policy is included. Do not expose this development server publicly. Events are retained until the local database is managed by the operator; the UI has no destructive reset.

## Next-move prediction (September 2026 update)

Restart `python run.py` and refresh the browser after updating. In Traffic lab, keep one investigation ID for one related sequence. Click **Add next demo observation** three times to build history; keep adding observations to see the ranked forecast change. The first forecast can be inconclusive. Up to ten demonstration observations are available per investigation. **New investigation** starts another sequence without deleting earlier events.

For your own observations, use **Analyze custom traffic** with the same investigation ID. Manual and synthetic demonstration histories are always separated. Arbitrary Normal/Uncertain/Attack scenario clicks remain detection tests and do not create meaningful sequence forecasts. Existing events without investigation metadata are preserved and excluded from forecasting history.

### What the model predicts

`backend/services/next_move.py` fits a random forest to the six traffic features from the previous three observations, plus the change from the first to the third observation. Its target is the labeled behavior on the **next recorded event**. Repetition of the current behavior is allowed. It does not predict a guaranteed next distinct stage, an attack timestamp, a particular target machine, an exploit, or an attacker's intent.

Classes are benign, reconnaissance, credential_access, lateral_movement, exfiltration, and denial_of_service. The built-in model is trained on synthetic episodes from `backend/utils/sequence_generator.py`; its scores are demonstration results, not research validation. Six aggregate features cannot establish these behaviors in real traffic. Authentication, host identity, endpoint and directional flow evidence are needed for stronger real-world modeling.

The next-move model is independent of the binary classifiers. Scores are uncalibrated model outputs. If the highest score is below 0.45, the UI says inconclusive. If any of the three observations falls outside the training feature ranges, it abstains. These checks do not establish safety or calibration. Forecast snapshots, investigation ID, evidence event references and model version are saved with each event. The model is persisted at `models/next_move.joblib` and restored on restart.

### Train on labeled sequences

Model registry now includes **Next-move prediction model**, separate holdout metrics, a downloadable synthetic sequence CSV, per-behavior results, and a sequence upload form. The existing binary `sample_traffic.csv` cannot train attack progression.

Required columns:

```text
episode_id,timestamp,attack_stage,packet_rate,failed_logins,unique_ports,avg_packet_size,connection_duration,syn_ratio
```

Use 48–50,000 rows, at least eight episodes, unique ISO 8601 timestamps with timezone per episode, finite nonnegative features and SYN ratio in [0,1]. Mark generated datasets with `data_source=synthetic`; otherwise uploaded provenance remains unverified. Do not invent episode membership or attack-stage ground truth for real measurements.

Whole episodes are ordered by start time. The earliest 75% define the training side and later episodes define holdout. Episodes crossing the time boundary are excluded. Windows are constructed independently within each episode and split, using three inputs and the subsequent label. Windows crossing gaps longer than 30 minutes are excluded. There must remain 24 training windows / 8 holdout windows and 4 earlier / 2 later episodes, with at least two training target classes. The persisted model is fitted only on the training side; the holdout is not refitted into it. Reported metrics include next-event accuracy, macro F1, a training-majority baseline and per-class support. Repeated tuning against this holdout is not an independent final evaluation.

This split design follows the leakage precautions in the [scikit-learn common-pitfalls documentation](https://scikit-learn.org/stable/common_pitfalls.html) and [time-dependent evaluation guidance](https://scikit-learn.org/stable/modules/cross_validation.html).

Live custom observations use server receipt time, not historical capture timestamps. Enter them in the actual observed order; use labeled sequence CSVs for offline training. Training and inference remain serialized by the application lock. Run one server process against this local workspace.

New endpoints:

- POST `/api/prediction/demo-step`: JSON investigation_id; adds one demonstration observation.
- GET `/api/prediction/example-csv`: download reproducible synthetic sequence data.
- POST `/api/prediction/train`: multipart file upload; invalid training leaves the saved model active.
